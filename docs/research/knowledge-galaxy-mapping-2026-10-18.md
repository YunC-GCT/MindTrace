## 1. 当前事实与设计边界

| 项目 | 已有事实 | 本草案约束 |
|---|---|---|
| KnowledgeUnit | 项目定义为结构化笔记，包含学科、章节、内容及复习状态 | 第一阶段一个 KnowledgeUnit ID 对应一个知识星球 |
| 独立知识概念 | 当前星系投影没有跨笔记概念归并身份 | “一个概念关联多篇笔记”是未来方案，不宣称已经存在 |
| Chapter | 学科内的自由文本，不能保证跨记录唯一 | 第一阶段按学科和规范化章节文本分组；不自动合并语义相似章节 |
| 节点投影 | 已有 id、label、subject、chapter、mastery、color | 位置和视觉状态属于派生结果，不反写知识事实 |
| 关系事实源 | 生产图谱读取 kg_edge 中 accepted 的关系 | 不恢复旧数组为第二事实源；不把 pending 推荐画成已确认关系 |
| 当前原生布局 | 按节点索引计算角度、半径及深度 | 后续改为稳定身份驱动的分组布局，不能依赖查询顺序 |

## 2. 知识对象与天体映射

以下为建议规则，确认后再转为实施规范。“星系、星团、知识星球”暂为本草案的视觉术语，不新增业务实体。

| 编号 | 业务对象 | 视觉对象 | 身份与归属规则 | 点击结果 |
|---|---|---|---|---|
| M-01 | Subject 学科 | 星系 | 每个学科一个稳定空间中心；NoteType 不用于划分星系 | 聚焦该学科 |
| M-02 | Chapter 章节 | 星团 | 学科内聚集；不同学科的同名章节不合并 | 聚焦该章节 |
| M-03 | KnowledgeUnit | 知识星球 | 保留原 ID；第一阶段不做跨笔记去重归并 | 首次选中，再次点击打开对应笔记 |
| M-04 | KnowledgeUnit 正文、例题 | 星球详情 | 现有内容在详情展示，不凭空拆成独立天体 | 沿用详情阅读流程 |
| M-05 | Prerequisites | 有方向的关系线 | 前置知识 → 当前知识；只有已接受关系参与 | 高亮两端，明确方向 |
| M-06 | Related | 无方向的弱关系线 | 同一对节点只展示一条；不表示学习先后 | 展示关联对象 |
| M-07 | 星云、尘埃、背景星点 | 装饰层 | 不对应知识数量，不持有业务 ID，不参与业务拾取 | 无动作 |
| M-08 | 未来跨笔记概念 | 候选聚合星球 | 需另行定义概念 ID、来源笔记集合、归并与拆分规则 | 多来源时先显示材料列表，不任意打开一篇 |

## 3. 空间映射与稳定性

| 编号 | 维度 | 建议定义 | 禁止或限制 |
|---|---|---|---|
| L-01 | 星系中心 | 不同学科使用持久稳定的布局锚点 | 新增学科不重排所有已有中心 |
| L-02 | 星团位置 | 章节聚集在所属学科星盘内 | 不同章节不能仅因标题相近自动归并 |
| L-03 | 星盘形态 | 螺旋臂作为柔性形态约束，关系布局决定局部结构 | 不强迫知识点机械排成一条螺旋线 |
| L-04 | 节点距离 | 同章优先聚集，accepted 关系提供局部吸引 | 距离不是相似度分数，也不代表掌握度 |
| L-05 | 前置方向 | 由箭头或明确的方向标记表达 | 不把靠近中心解释为“必须先学” |
| L-06 | Z 深度 | 为星盘提供真实厚度、透视与遮挡 | 第一阶段不映射难度或重要程度 |
| L-07 | 身份稳定 | 固定 ID、固定布局种子、稳定排序；已有坐标可缓存 | 禁止用数组索引或每次随机数作为长期位置依据 |
| L-08 | 增删节点 | 新节点放入所属星团，局部避让；删除只释放对应位置 | 不因一次修改让全图重新洗牌 |
| L-09 | 修改学科/章节 | 仅移动受影响节点，保留选中身份；过渡可减少动效 | 不因位置变化修改关系或笔记 ID |
| L-10 | 缓存与版本 | 缓存按布局版本和稳定 ID 关联；失效可确定性重建 | 缓存不是知识数据事实源；存储方式待实施时确定 |
| L-11 | 动态效果 | 缓慢尘埃流动、轻微光效；用户拖动时响应优先 | 第一阶段不让业务星球持续公转，避免点击目标漂移 |

建议布局顺序：学科分组 → 章节分组 → 生成稳定锚点 → 星盘骨架 → 局部关系约束与避让 → 输出三维坐标。

## 4. 视觉属性映射

| 属性 | 唯一主要含义 | 建议规则 | 缺失或异常处理 |
|---|---|---|---|
| 色相 | 学科归属 | 同学科保持主色，章节使用有限色调变化；配合文字图例 | 未分类使用中性色，不能伪造学科 |
| 球体大小 | 结构重要性 | 第一阶段统一基础大小；后续可按已确认关系数量做有上限的映射 | 无关系时使用基础大小，不直接按笔记字数放大 |
| 掌握光环 | 掌握程度 | 使用独立的环形进度或表面状态，详情显示数值 | 未知与 0 分开；不得将未掌握球体暗到不可见 |
| 呼吸提示环 | 复习紧迫性 | 来源于复习调度状态；减少动效时改静态标记 | 无复习信息不推断“已掌握” |
| 选中外圈 | 交互选中 | 最高视觉优先级，独立于掌握与复习状态 | 点击空白取消选中 |
| 表面材质 | 三维形体识别 | 有法线的平滑球体、适度粗糙度、克制高光 | 不使用四面体替代知识星球 |
| 连线样式 | 关系类型 | 前置线有方向，关联线无方向；不只靠颜色区分 | 未支持的 derived 不冒充 related |
| 标题 | 真实知识名称 | 保留当前标题样式；投影随节点变化，重叠时按优先级显示 | 不改写用户标题；全文可在选中或详情中读取 |

视觉优先级建议：选中对象 → 选中对象的直接关系 → 复习提示 → 普通知识节点 → 装饰层。颜色不是唯一的信息渠道。

## 5. 视距与交互分级

| 级别 | 主要对象 | 标题策略 | 连线策略 | 交互 |
|---|---|---|---|---|
| 全景 | 学科星系、整体星盘 | 学科名及真实节点计数 | 默认不画逐节点连线 | 选择学科并聚焦 |
| 中景 | 章节星团及部分知识星球 | 章节名，优先保留选中对象标题 | 默认收起，选中后显示直接关系 | 选择章节、拖动旋转、缩放 |
| 近景 | 单个知识星球 | 显示知识标题，做遮挡与碰撞处理 | 显示选中节点的一跳关系，区分方向 | 首次选中，再次点击打开详情 |
| 详情 | KnowledgeUnit 内容 | 展示完整标题及来源 | 在详情说明关系，不操作后台场景 | 返回后恢复视角和选中身份 |

层级切换依据节点的屏幕投影尺寸与可读性确定，使用不同的进入/退出阈值避免反复闪烁；具体阈值待真机原型测量，不写成已验证常量。

## 6. 数据异常与边界表

| 场景 | 规则 |
|---|---|
| 无任何知识数据 | 展示空态入口；可有装饰背景，但不能生成假的业务星球 |
| 仅一个节点 | 居中聚焦，不制造虚假关联或填充节点 |
| 学科或章节缺失 | 展示“未分类”或“未分章”分组；保留原数据，不擅自回写 |
| 不同 ID 的同名笔记 | 保留多个节点；标题相同不是合并依据 |
| 同一 ID 被重复查询 | 去重为一个业务节点 |
| 关系端点不存在 | 不画悬空连线，不生成占位知识；供数据诊断识别 |
| pending / rejected 关系 | 不参与已确认关系布局；若未来展示推荐，必须有独立图例和确认操作 |
| 跨学科关系 | 保留关系事实，选中后按需展示；不能因分组直接丢弃 |
| 前置关系形成环 | 保留原始事实并提示数据问题；不得宣称一定存在拓扑学习顺序 |
| 高密度星团 | 聚合显示、限制标签和装饰密度；始终可搜索或定位真实节点 |
| 减少动效或性能不足 | 优先降低装饰和粒子；保持业务球体、拾取和阅读能力 |

### 9.1 远端核对记录

### 9.2 两种保留方案

| 对比项 | Web 渲染（保持现状） | 原生 3D（当前优化对象） |
|---|---|---|
| 技术入口 | GalaxyWebAdapter → ArkWeb → Three.js | GalaxyComponent3DAdapter → Component3D / ArkGraphics3D |
| 场景资源 | tools/galaxy3d-preview/src 与 rawfile/galaxy3d/index.html | rawfile/galaxy3d/native/galaxy-scene.glb |
| 使用场景 | 现有模拟器兼容路径；原生能力缺失或加载失败时承接 | 具备原生能力且场景加载成功的设备 |
| 布局和视觉 | 原有相机、布局、球体、星点、标题及低性能兼容模式全部保留 | 原生球体网格、材质、光照、三维坐标及标签投影独立维护 |
| 交互实现 | 既有 Web 事件和消息桥 | ArkUI 手势与原生 Camera.raycast |
| 共享边界 | 既有 GalaxyGraphSnapshot、业务 ID、关系语义、选中/打开笔记回调 | 同左；不要求照搬 Web 的底层坐标或视觉实现 |
| 本轮禁止事项 | 不更换布局算法，不移除 Web 内部降级，不重新构建覆盖页面 | 不将原生优化隐式扩散到 Web，不伪称两端画面完全一致 |

“模拟器用 Web、真机用原生”是当前使用场景描述，不是新增硬编码设备分流规则。保留现有能力检测：有 Graphics3D 能力先尝试原生，失败切 Web；无能力直接 Web。本次不改模拟器识别策略。

### 9.3 旧 2D 与错误状态

| 项目 | 处理 |
|---|---|
| ReviewGraphView.ets | 删除独立旧 2D 页面；Git 历史可恢复 |
| 宿主旧 2D import 和挂载分支 | 删除，不再作为第三种渲染器 |

后续验收必须分别记录 Web 与原生结果，不以原生真机通过替代模拟器验收；共享数据契约若需修改，必须单独评估 Web 兼容性。
